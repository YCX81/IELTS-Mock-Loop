# Bilingual Intensive Reading Skill | 双语精读

## 一、目标

让学习者在完成一次精读后能够：

1. 用中文准确复述文章的核心内容与论证路线；
2. 真正理解关键长句，而不是只看懂译文；
3. 掌握一组可以在新语境中使用的词块、搭配和句型；
4. 识别作者的态度、修辞和段落功能；
5. 通过翻译、仿写、复述和间隔复习把“看懂”变成“会用”。

## 二、触发条件

用户提供英文文章、截图、文件、链接或文章片段，并表达以下任一意图时启用：

- 精读、逐句讲解、双语学习；
- 分析长难句、词汇、搭配或语法；
- 学外刊、新闻英语、考研英语、四六级或写作表达；
- 将某篇文章制作成学习材料、讲义或复习卡。

若用户只说“精读这篇”，默认使用「标准模式」，学习者水平按 B1–B2 处理。不要因缺少可选参数而阻塞任务。

## 三、可选参数

尽量从用户话语中推断；用户未指定时采用默认值。

| 参数 | 可选值 | 默认值 |
|---|---|---|
| `level` | A2–B1 / B1–B2 / B2–C1 / C1+ | B1–B2 |
| `mode` | 快速 / 标准 / 深入 / 互动 | 标准 |
| `goal` | 阅读理解 / 词汇 / 长难句 / 写作 / 考试 / 综合 | 综合 |
| `variety` | 英式 / 美式 / 保持原文 | 保持原文 |
| `exercise` | 无 / 少量 / 完整 | 按用户要求 |
| `chunking` | 一次完成 / 分段学习 | 依文章长度决定 |
| `coverage` | 重点精读 / 完整保真 | 从用户措辞推断 |
| `direction` | 外刊精读 / 技术理解 / 考试写作 | 外刊精读 |
| `research` | 纯文本 / 素材延申 / 背景补充 | 原型栏目风默认素材延申 |
| `reference_examples` | 不加 / 少量素材 / 栏目增强 | 跟随 `research`，原型栏目风默认少量素材 |

### 模式预算

- **快速模式**：约 10–15 分钟；讲 3–5 个高价值表达、1–2 个难句、1 个练习。
- **标准模式**：约 30–45 分钟；讲 8–12 个表达和所有关键难句；至少 3 个 A 层核心表达要达到原型栏目级展开密度。练习、表格和复习卡只在用户要求或明显需要交付学习材料时追加。
- **深入模式**：约 60–90 分钟；增加语域辨析、修辞、篇章结构、仿写和复习计划。
- **互动模式**：先给预读任务，再按段落推进；每轮让学习者先作答，再讲解。若用户要求一次性完成，则不要停下来等待。
- **完整保真模式**：当用户说“完整”“不要省略”“逐段/逐句”“生成完整文档”“保留全部内容”时启用。目标是覆盖原文全部正文，而不是挑重点。长文必须分批或分文件输出，不能为了塞进一轮而压缩成摘要。完整保真只约束覆盖范围，不等于输出表单化；仍然要保持外刊精读栏目稿的自然节奏。

## 四、核心原则

### 1. 以学习价值筛选，不做逐词词典

只讲影响理解、值得复用、容易误解或具有表达价值的内容。基础词若不构成障碍，不必展开。文章越长，越要克制选择。

若 `coverage=完整保真`，这里的“筛选”只影响讲解深浅，不影响覆盖范围。每个原文段落都必须被保留、翻译或明确说明其处理方式；不得把多个章节压缩成一句概述后仍称为“完整精读”。

短新闻、短评论、短故事即使没有显式要求“完整保真”，标准模式也应默认接近完整带读。800 词以内的材料要按原文顺序覆盖全部主要句段；普通事实句可以合并略讲，但不能无声跳过含标题、副标题、核心隐喻、品牌/人物声明、关键公众反应、专家评论、转折句或收束句的段落。

### 2. 翻译先自然，再解释对应关系

译文应像正常中文，而不是英文语序的搬运。必要时说明哪里做了增译、拆译、转译或语序调整。不得为了“忠实”制造生硬中文，也不得为了“好听”改掉原意或语气。

### 3. 语法要回答“它在这里做什么”

不要只贴术语。每次语法分析至少说明：

- 句子主干是什么；
- 修饰成分指向哪里；
- 作者为什么用这种结构；
- 去掉或改写后，语气和重点如何变化。

长句优先使用“主干 → 从句/分词/插入语 → 逻辑关系 → 重组译文”的顺序拆解。

### 4. 词汇必须放回语境

对核心词或词组，按需提供：

- 本句义与常见义的区别；
- 固定搭配、介词和常见句型；
- 正式度、褒贬色彩与适用场景；
- 一个贴近学习者生活或文章主题的双语例句；
- 1–3 个近义表达及差别。

不要机械罗列词源、同义词或三四个例句。只有确实帮助记忆或迁移时才加入。

### 5. 解释作者如何写，而不只是写了什么

关注标题双关、对照、比喻、借代、语气、信息顺序、数据与人物的配合、段落转折和收束。明确说明某个表达对画面、节奏、立场或论证的作用。

### 6. 风格补充

讲解口吻参考中文外刊精读栏目：中文解释为主，表达自然、有画面感，不像词典，也不堆语法术语。遇到好表达时，不只解释意思，还要说明它为什么好、在文章里起什么作用，以及学习者以后能如何迁移使用。

当用户说“按原型”“栏目格式”“外刊精读”，或你需要判断输出是否像栏目稿时，先读 [references/column-style.md](references/column-style.md)。核心要求：自然导语、数字编号逐句推进、少用表单标签、A 层表达深讲但数量受控。

避免逐词贴词典释义、堆语法术语、强行追热点、把语言学习写成鸡汤。可以有一点轻松判断，但判断必须从原文表达里长出来。

### 7. 难度与方向标定

默认方向为“外刊精读”：对标中文外刊精读栏目，而不是技术手册、源码注释或百科词条。优先讲文章主线、语言表达、长难句、词块迁移和写作仿用。每篇材料都要先抓“这篇文章真正想让读者看见什么”，再决定讲哪些词句和背景。

默认难度按 B1-B2 处理：

- 中文解释要承担理解任务，把抽象词、长句和背景关系讲清楚；
- 不默认读者已经懂专业背景，但也不把精读变成专业课；
- 语法术语只在帮助拆句时出现，不作为讲解主体；
- 例句要自然、可迁移，优先贴近学习、职场、城市生活、科技、消费、社会议题等通用场景；
- 专业术语要讲“本文怎么用、为什么重要”，不要扩展成无边界的技术说明。

默认方向按这个优先级组织：

1. **文章主线**：作者/文档想让读者相信、理解或采取什么行动。
2. **表达价值**：哪些词块、句型、比喻、对照或信息顺序值得学习者以后复用。
3. **必要背景**：只补足理解原文所需的技术、历史或社会背景。
4. **细节材料**：命令、API、项目清单、许可证、链接等保留覆盖，但讲解密度要低于核心论证。

处理 README、设计文档、技术文档时，先判断文档功能：

- README 通常要回答：这是什么、解决什么痛点、为什么可信、怎么开始、哪些责任仍在用户、去哪里看更深细节。
- 设计文档通常要回答：问题约束是什么、已有方案为什么不够、核心取舍是什么、每个机制如何回应约束。
- API/命令/相关项目列表通常是支持信息，不应抢走主线。可以用表格或简洁说明覆盖，除非用户明确要求逐项深入。

完整保真不等于平均用力。完整保真要求不漏原文，但仍要做密度分层：

- A 层：中心观点、关键转折、核心机制、好表达，要精讲。
- B 层：支撑例子、重要说明、普通长句，要讲清楚。
- C 层：链接、许可证、相关项目、重复性命令，可简洁翻译或表格化。

输出的开头必须有“主线抓手”，用 3-5 句话告诉学习者：这篇文章最重要的不是哪些散点词汇，而是怎样的一条逻辑线。若生成结果虽然覆盖很全，但读完后抓不住文章方向，就视为失败。

默认输出版式必须贴近中文外刊精读栏目，而不是课件表单：

- 顶部先给自然中文标题和 1-3 段导语，导语要交代事件、背景或文章真正要读者看见的问题。
- 不要在正文开头输出参数头或任务说明，如 `来源`、`日期`、`模式`、`学习者水平`、`方向`。来源和日期只有在行文自然需要时融入导语。
- 需要完整保留原文、导出学习文档或处理长文时，可用 `01 原文`、`02 精读`；若目标是最贴近公众号栏目稿，可省略独立 `01/02` 分区，导语后直接用数字编号带读。
- 逐句讲解用数字编号推进：编号、英文原句、自然中文译文，然后用自然段讲词、句、语气、画面、文章作用和迁移例句。编号用 `1`、`2`、`3`，不要用 `P1`、`P2`、`P3` 这种文档审计式编号。默认不要用 Markdown 引用块 `>` 包住每个英文句子，除非用户要求 Markdown 学习文档、对照排版或需要清楚区分长引文；栏目稿更适合直接写原句和译文。
- 不要默认输出 `## 0. 先读懂这篇`、`覆盖清单`、`原文逐段精读`、`篇章地图`、`自然译文`、`段落作用`、`表达提示`、`句子骨架`、`重点表达`、`为什么这样写`、`迁移使用` 这一类表单式栏目。只有在用户明确要求语法表、复习卡、覆盖报告或练习材料时才显式分栏。
- 主线抓手要融入导语或精读前的短段落里，不要写成机械字段。讲解密度分层用于内部取舍，默认不作为外显清单输出，除非用户要求诊断讲解策略。
- 普通精读单元最多抓 1 个主点和 1-2 个副点；标题句、核心长句或信息密度很高的句子可以抓 1 个主点和 2-4 个学习点，但必须有主次，不要平均铺开。不要因为原文完整保真，就把每段都平均写成“译文 + 作用 + 提示”的固定三件套。
- 表格、练习和复述放在正文精读之后作为收尾模块；不要让表格替代讲课式解释。

高价值表达深挖规则：

- “每个精读单元最多抓 1 个主点”不等于浅讲。若这个主点是标题词、核心隐喻、社会议题词、作者立场词、技术文档里的关键机制词，必须把这 1 个点讲深，而不是只给一条 `表达提示`。
- A 层表达要像一小段栏目讲解：先讲本句义，再讲词形、字面画面或构词逻辑；接着说它为什么不是普通说法、语气重在哪里、在文章里推动了什么判断；最后给至少 2 个可迁移双语例句。若这个表达有常见替换，还要自然引出 2-3 个相近表达，并说明差别，而不是只列同义词。
- 标准模式至少挑 3 个 A 层表达写成“原型式长讲”；短文少于 3 个 A 层表达时，所有 A 层表达都要长讲。长讲不是加小标题，而是连续用自然段讲透：本句义、字面画面或构词、普通说法差别、语气边界、文章作用、外部素材、2 个以上迁移例句，以及 2-3 个相近表达。若文章标题中有核心表达，优先长讲标题表达。
- 标准模式通常只保留 3-4 个 A 层表达；800 词以内的短文或节选最多 5 个，除非用户明确要求“深入/完整/多拓展”。其他好表达按 B/C 层收束，避免把栏目稿写成表达大全。
- A 层表达必须过“深挖六件套”：本句义；字面画面、构词或常见搭配；与普通说法的差别；语气和使用边界；在文章里的作用；至少 2 个可迁移双语例句。若外部素材可用，素材必须嵌入这个表达的讲解，而不是另起一段资料补充。
- B 层表达讲清本句义、语气和 1 个迁移例句即可；C 层表达只需一句话点明，不硬凑拓展。
- 深挖时不要机械使用“小标题”。要连续讲出字面画面、语气边界、文章作用和迁移场景；近义表达必须服务于迁移，每个替换都要说明适用边界。
- 迁移例句要有现实语境和中文译文，不能只是把词塞进空句子。优先选择学习、职场、城市生活、平台经济、技术产品、教育、公共服务等稳定场景；除非用户明确要求时事写作，不要强行追热点。
- 若使用影视、文学、考试或新闻素材，必须贴着当前表达就地解释；素材的首要任务是充当“这个词/短语/句型如何使用”的真实例句或迁移场景，而不是佐证文章议题。具体规则见 [references/material-extension.md](references/material-extension.md)。
- 如果查到的外部信息只是事件背景，而不能帮助解释某个表达、句型或写作迁移，就只在导语中用一句话自然吸收，或干脆不用。

### 8. 例句服务于迁移，不追逐热点

例句应自然、准确、与学习者水平相符，并尽量复用原表达的真实搭配。除非用户需要时事写作，不要为了“接地气”强行绑定热搜、名人或短期新闻。

### 9. 素材延申，不写查证报告

本 skill 可能运行在 Codex 或其他 agent 工具中。只要当前环境具备联网、浏览、搜索或检索工具，并且用户要求“原型栏目”“素材延申”“补影视/文学/考试/热点素材”“深挖和拓展”，就必须先围绕 1-3 个 A 层表达实际调用搜索/浏览工具。完整原文只表示不必找原文，不表示不找素材。

把“搜索”当作工具动作，不是思考动作。不能用模型记忆、常识或训练中见过的材料冒充已搜索素材；在 Codex 中，若 `web.run`、浏览器搜索、插件搜索或等价检索工具可用，正式写作前必须至少调用一次。若当前 agent 没有任何搜索/浏览工具，就不要点名具体影视、真题、新闻或网页素材；可改用泛化迁移例句，或在给用户的简短说明中说当前环境无法联网搜索。

素材延申是为表达服务，不是背景查证报告。用户说“不要核验”“不要查背景”时，仍保留表达素材搜索；只有用户明确说“不要联网”“不要外部素材”“只基于原文”时才跳过。正式输出中不要写搜索过程、来源清单、查证报告、访问失败说明或“先抓三个核心表达”。

素材必须贴在对应表达下面，并形成“解释表达 -> 引入真实语境或例句 -> 回到原句或迁移用法”的闭环。优先把素材写成表达例句、近义替换和跨话题迁移，不要只用素材证明文章主题。详细规则见 [references/material-extension.md](references/material-extension.md)。

### 10. 不虚构出处

考研真题、影视台词、词源、数据、人物身份和新闻背景只有在能够确认来源或由用户材料明确提供时才使用。无法确认时直接省略，不得凭印象编造。涉及最新事件、政治、法律、医疗、金融或争议事实时，使用当前环境可用的联网/检索工具查找可靠来源；语言学习不依赖该背景时，可简要说明“此处只分析语言”。

### 11. 保持语境与尊重

遇到冒犯性、性别化、族群化、粗俗或身体描写词汇，应解释其语气、风险和使用边界，不把“认识这个词”误导成“适合主动使用”。

### 12. 版权与篇幅

- 用户直接提供的文本，可在学习所需范围内逐句引用和转化。
- 仅提供网页链接时，不大段复刻受版权保护的全文；选取必要短句精读，其余内容概述。若链接无法访问、付费墙阻挡，或只拿到标题/摘要，不得伪造完整逐句精读；只能基于可见短句做受限精读，并用一句话请用户粘贴原文以继续完整带读。
- 用户只粘贴文章片段时，标题或导语要自然标明“节选精读”或“先读这段节选”；除非用户提供完整正文，不要写“全文”“完整精读”。
- 超过约 800–1,000 英文词时，优先按段落或主题分批处理，并先给全文地图，避免一轮输出失控。

## 五、执行流程

### Step 1：整理文本

1. 保留标题、段落、引号、破折号和必要格式；修正常见复制噪声，但不擅自改写原文。
2. 判断 `research`：用户说“像原型一样”“补影视/文学/考试/热点素材”“栏目增强例证”，或点名雅思、托福、GRE、GMAT、SAT、四六级、考研等素材时，设置 `research=素材延申`、`reference_examples=栏目增强`。用户明确说“不要联网”“不要外部素材”“只基于原文”时设为 `纯文本`。用户只说“不要核验”“不要查背景”时，仍保留 `research=素材延申`，但不做背景查证报告。
3. 若用户提供的是链接、标题线索、截图或不完整摘录，且当前环境有联网/检索工具，先尝试获取原文或可靠摘录；若用户要求素材延申，即使已粘贴完整原文，也必须围绕 1–3 个 A 层核心表达搜索可用素材，而不是做背景来源报告。这个“先搜索”动作只改变写作前的准备，不改变正文开场；正文仍从文章主线自然进入。
4. 标出来源、日期和作者，仅在用户提供或已确认时写出。
5. 根据篇幅切分：
   - 300 词以内：通常可完整精读；
   - 300–800 词：标准模式默认按原文顺序覆盖全部主要句段，普通事实句可合并略讲，A/B/C 分层控制讲解密度；
   - 800 词以上：先总览，再分段或分篇精读。
6. 估算难度，并判断主要障碍来自词汇、句法、背景还是篇章逻辑。

若用户要求完整保真：

1. 内部先建立覆盖清单：列出原文所有一级/二级标题，必要时统计每节大致段落数。这个清单默认不外显，除非用户要求审计或质疑遗漏。
2. 按原文顺序分批处理，每批可以用一句自然提示说明范围，例如“这一部分先读开头到 `Where Loops Work`”，不要默认写成 `覆盖原文：...` 的审计标签。
3. 每个原文段落或句群至少提供自然译文；重要句群再用自然段讲主干、好表达、语气、文章作用和迁移。不要把每个段落固定写成 `自然译文 / 段落作用 / 表达提示`。
4. 长段应拆成可读的句群或重点句，不要用 `P1`、`P2` 逐段审计。默认用栏目式编号 `1`、`2`、`3` 推进。
5. 代码块、图示、表格、列表、脚注和链接引用不得无声删除。可不逐字符讲 ASCII 图，但要保留或说明其功能。
6. 如果因长度必须分文件，文件名追加 `第01部分`、`第02部分`，并在每部分末尾用自然语言说明下一部分从哪里继续。
7. 输出标题不得写“完整”或“全文”除非本次交付或系列交付确实覆盖了全部原文正文。

### 输出文件命名

当用户要求导出或保存为 Markdown、DOCX、PDF、HTML 等文档文件时，文件名必须来自当前学习材料，而不是来自 skill 名。不要把输出文件命名为 `bilingual-intensive-reading`、`skill` 或类似通用名称，除非用户明确指定。

按以下优先级确定文件名：

1. 用户明确给出的输出文件名；
2. 用户上传文件的原始文件名去掉扩展名；
3. 文章原始标题或自然中文标题；
4. 根据文章内容生成的简短中文标题。

文件名清洗规则：

- 保留能识别文章主题的核心词，必要时追加 `-双语精读`，例如 `中国茶饮挑战美国咖啡文化-双语精读.md`。
- 移除 Windows 不允许的字符：`< > : " / \ | ? *`，并压缩多余空格。
- 文件名过长时保留主题核心，通常控制在 80 个字符以内。
- 分段输出时追加序号，例如 `外卖骑手处境-双语精读-第01部分.md`。
- 多篇文章批量输出时，每篇都使用各自标题或源文件名，不要共用同一个通用文件名。

### Step 2：写自然导语

逐句讲解前，先像中文外刊精读栏目一样给读者一个现实入口：

1. 标题要像文章标题，不像课程标题。可以保留原题张力，也可以改成自然中文标题。
2. 导语用 1-3 段写清：这篇材料表面上讲什么，真正想让读者看见什么冲突、反差、变化或取舍。
3. 不要外显 `一句话主旨`、`主线抓手`、`文章路线`、`作者态度`、`本篇难点`、`讲解密度分层`。这些判断要融入导语。
4. 不要输出“先抓三个核心表达”“本文重点看 A/B/C”“我先搜索了影视/文学/考试素材”这类内部规划句。可以自然写成：“这篇文章表面看是……，真正值得读的是……这一组词怎样失控。”如果草稿开头出现表达清单或素材清单，发布前必须改写成栏目式导语，并把素材移回对应表达段落。
5. 需要介绍来源时，用自然句写，例如“今天读一篇关于……的英文文章”，不要在开头列参数表。
6. 使用外部素材时，导语只吸收对理解有帮助的背景事实，不能写成查证报告。不要写 `我做了轻量核验`、`核验参考`、`当前检索中未能访问` 或独立来源列表。
7. 不要在导语里集中展示外部素材。影视、文学、考试和新闻素材应随对应表达进入讲解正文；导语里最多留下一个真正帮助读者进入主题的背景入口。
8. 长文分批时，只用一句话自然说明本篇读到哪里；不要把分批计划写成审计清单。

导语的任务是让读者愿意读下去，不是提前提交结构分析报告。

### Step 3：带读段落

段落功能必须讲，但要融入自然讲解，不要固定写成 `段落作用：`。

默认做法：

- 遇到核心段落，先点出“这段真正把问题推到哪里”。
- 遇到普通信息段，讲清一两个必要信息后继续推进。
- 遇到长段，拆成句群或关键句，不要用 P1/P2 做逐段审计。
- 遇到标题、小标题、转折句，要说它如何改变文章方向。

### Step 4：逐句精读

默认采用栏目稿式逐句精读，不采用固定表单塞满每个句子。每个入选句子按下面节奏处理：

N

> English sentence.

自然中文译文。

随后用 2-6 个自然段讲解，不要机械分栏。讲解顺序通常是：

1. 先用自然句说这句话在文章里承担什么功能，或它为什么值得停下来讲。
2. 再挑 1-3 个最有学习价值的表达、搭配、句型或修辞讲透。
3. 遇到长难句时，用自然语言拆主干，例如“这句话的主干其实是……”，再说明修饰成分如何补充信息。
4. 遇到好表达时，说清它为什么好：比普通说法更有画面、更有语气、更能制造反差，还是更能推进论证。
5. 给 1-3 个可迁移例句或同义替换；例句要自然贴近学习、职场、城市生活、科技、消费、公共议题等通用场景。

若本句的主点是 A 层高价值表达，允许超过 6 个自然段，但必须仍像一段讲课稿，而不是改成表格或复习卡。A 层表达的默认深挖顺序是：

1. 先把原句意思讲明白，让读者知道这个表达在本句里具体指什么。
2. 如果词形、构词或字面画面有帮助，就解释它如何帮助记忆，例如 `under + class`、`load-bearing`、`paper over` 这类表达。
3. 说明它和普通说法的差别：不是简单的 `poor people`、`hide`、`important`、`give up`，而是多了怎样的结构意味、批评意味、画面感或责任判断。
4. 讲它在文章里的作用：是压低语气、制造反差、点出作者立场、呼应标题，还是把抽象问题变成具体画面。
5. 给至少 2 个迁移例句，每个都有英文和自然中文，并尽量复用原表达的真实搭配。
6. 若适合积累近义表达，再给 2-3 个相近表达的差别与例句。不要把相近表达写成词表，要像“顺手再积累几个说法”那样自然接上。

只有在用户明确要求语法表、复习卡、考试笔记，或句子结构确实复杂时，才额外使用 `主干`、`修饰`、`逻辑`、`可仿写句型` 等小标题。即使用小标题，也要简短，不能把讲解变成模板填空。

默认禁止把每个句子写成这些显性标签：

- `自然译文：`
- `段落作用：`
- `表达提示：`
- `为什么好：`
- `迁移使用：`
- `句子骨架：`

这些内容要通过自然过渡句完成。例如：

- “这句话的关键在 `...`。”
- “这里不是简单说……，而是在写……。”
- “这个词比普通的 `...` 更有……语气。”
- “以后写……话题时，可以借这个结构。”

讲解密度控制：

- 标题句、转折句、核心长句、漂亮表达、社会议题词、关键机制词可以精讲，尤其要深挖可迁移表达。
- 数字密集段落先讲数字制造的比例感和作者判断，不要逐个数字平均复述；采访引语先讲它把哪个抽象判断变成了具体消费心理、身份感或现场画面。
- 普通信息句只讲清楚，不硬凑表达、例句和语法。
- 普通句最多抓 1 个主点和 1-2 个副点；核心句、标题句和信息密度高的长句可以抓 2-4 个学习点，例如“长句主干 + 一个核心表达 + 一个语气词 + 一个可迁移句型”。但必须讲出主次，不要把每个点都写成同等长度。
- 如果一个表达已经按 A 层深挖，同一句里的其他点要明显收敛，避免把读者注意力拆散。

#### 逐句选择规则

以下规则只适用于 `coverage=重点精读`。若用户要求完整保真，不要用“选择规则”跳过原文段落；只能调整讲解深度。

若材料少于 800 词且用户没有明确要求“只挑重点”，不要把重点精读理解成无声删段。可以把简单句合并到相邻精读单元，但核心隐喻、声明、公众反应、专家评论和结尾回扣必须出现。

优先讲：

- 标题及副标题；
- 标题和副标题中的双关、隐喻、仿写或品牌文化暗示；
- 含核心观点或转折的句子；
- 长难句与压缩结构；
- 多义词、地道搭配和语域明显的表达；
- 有修辞、画面或立场的句子；
- 能迁移到写作或口语的句型。

可以略讲或合并：

- 重复信息；
- 仅含专有名词和简单事实的句子；
- 低频且不影响理解的细枝末节。

### Step 5：主题回收

逐句讲完后，可以用一小段把镜头拉回全文，但不要默认输出 `篇章地图`。

回收时优先回答：

- 文章最后把读者带到了什么判断？
- 标题、开头和结尾怎样互相照应？
- 哪个表达或隐喻贯穿全文？
- 这篇文章真正留下的问题是什么？

若文章存在偏见、证据不足或替代解释，可简洁指出，但不要把语言课变成漫无边际的立场辩论。

对于 README、设计文档和技术文档，也要用自然段回答“这份文档最想降低读者哪种不确定性”，不要默认列出读者、承诺、路径、风险边界的表单。

### Step 6：今日带走与复习

正文主体先完成栏目稿式精读。不要让练习、表格、复述或复习计划抢走正文节奏。

当用户要求练习、输出学习材料，或深入模式确实需要收束时，才在正文后追加 `03 今日带走`。标准模式默认不生成完整课程包。

可选收尾内容：

- **今日真正要带走的 3-5 个理解**：必须是文章主线层面的，不要只用词汇表替代理解总结。
- **重点表达**：选 6-12 项；优先用自然段或短列表，不要默认用大表格。
- **可带走句型**：只选真正可复用的结构，给出跨主题仿写例句。
- **主动练习**：用户要求时生成 3-5 题，混合内容理解、英译中/中译英、选词填空、长句重组、仿写和 80-120 词摘要。
- **一分钟复述**：深入模式或用户要求时提供 3-5 个英文提示词和一份简洁参考复述。参考复述不要照抄原文。

答案放在练习之后，避免学习者第一眼看到。Markdown 可使用折叠区：

```html
<details>
<summary>参考答案</summary>
...
</details>
```

### Step 7：间隔复习

深入模式追加：

- **当天**：朗读重点句两遍，完成仿写；
- **第 1 天**：遮住中文，口译 5 个表达；
- **第 3 天**：做中译英与一分钟复述；
- **第 7 天**：用 5 个核心表达写一段新主题短文。

## 六、水平适配

### A2–B1

- 中文解释更多，句法术语更少；
- 补充发音、词形和基本搭配；
- 例句短而清楚；
- 每次核心表达不超过 8 个。

### B1–B2

- 平衡翻译、句法、搭配和篇章；
- 强调多义词、固定搭配和长句拆分；
- 安排少量中译英和复述。

### B2–C1

- 增加语域、近义差别、作者态度和修辞；
- 讨论信息结构与句型选择；
- 仿写更接近新闻、议论文或学术表达。

### C1+

- 减少基础释义；
- 强调搭配限制、语用、隐含立场、论证质量和风格模仿；
- 可要求英文释义、英文摘要和改写。

## 七、考试与写作专项

用户目标为考试时，在常规精读后增加：

- 可能的命题点：指代、态度、推断、主旨、词义猜测；
- 干扰项如何利用偷换概念、范围扩大或因果倒置；
- 2–3 个可用于作文的句型，但必须说明适用语境；
- 真题出处只有能确认时才引用。

用户目标为写作时，增加“表达升级”栏目：

- 原文表达；
- 普通表达；
- 更自然或更正式的改写；
- 哪些词不能随意互换；
- 一道跨主题仿写。

```markdown
[1-3 段自然导语。讲清文章表面话题和真正主线；不要列参数、搜索过程、来源清单或素材清单。]

接下来一起精读：

1

[English sentence.]

[自然中文译文。]

[自然段讲解：普通句抓 1 个主点；A 层表达按栏目式长讲；素材延申只放在对应表达下。]

[English sentence.]

```

## 九、质量检查清单

输出前逐项确认：

- [ ] 中文译文自然、准确，保留原文语气；
- [ ] 难句讲清主干与逻辑，词义解释贴合本句语境；
- [ ] A 层表达已讲清本句义、字面画面、语气边界、文章作用、迁移例句和近义差别；
- [ ] 标准模式 A 层表达数量受控，通常 3-4 个，短文或节选最多 5 个；
- [ ] 表达拓展仍服务于原文主线，没有为了“多讲”而离题展开成词典、百科或热点评论；
- [ ] 外部素材来自用户材料或可靠来源；未确认出处时没有编造；
- [ ] 用户要求素材延申且搜索工具可用时，已经实际调用搜索/浏览工具；没有用模型记忆冒充联网搜索；
- [ ] 素材延申嵌入具体表达讲解，主要作为表达例句、近义替换或迁移场景；没有只拿来佐证文章议题；
- [ ] 正文没有搜索过程、查证报告、访问失败说明、来源清单或“先抓三个核心表达”；
- [ ] 既讲语言，也讲句子在段落和全文中的作用；
- [ ] 版式像中文外刊精读栏目：自然导语、数字编号、讲课式自然段，不是表单式讲义；
- [ ] 原文展示范围和精读范围一致；若后文精读了声明、评论者句子或补充段落，原文区也应包含或自然说明来源；
- [ ] 没有把标准模式写成课程包；练习、表格、复述和复习安排只在用户要求或深入模式确实需要时出现；
- [ ] 开头和结尾都抓住了文章主线，能说明“这篇材料真正要读者理解什么”；没有把边缘信息、API 列表、相关项目或许可证讲成和核心论证同等重要；
- [ ] 篇幅与用户模式、水平和文章长度相匹配；
- [ ] 敏感词汇标明语气和使用边界；
- [ ] 网页文章没有被大段复制；若只是片段或重点精读，没有写成“全文/完整”。
- [ ] 800 词以内材料的标准模式没有无声跳过关键段落；若合并普通事实句，读者仍能看出原文信息已被吸收。

## 十、调用示例
